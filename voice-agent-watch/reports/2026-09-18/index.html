电话语音日报

电话语音日报｜2026-09-18

2026-09-18北京时间

今天最有价值的不是又一个“会说话”的 Demo，而是两块更贴近你目标的基础设施：一块负责什么时候升级到电话，另一块负责电话里到底听清了什么；耳机侧的佩戴判断、播放打断与文字未读仍要由移动端自己补。

1. Ringback：把“普通提醒 → 重要时通话”做成了可自托管的升级链

今天补录一个较早但高度匹配的开源项目 Ringback。它给任意 MCP Agent 暴露两组工具：平时可走 ntfy / Pushover 或 SIP 振铃提醒，Agent 判断需要真人介入时再发起双向语音；通话支持插话，用户说话时可以打断 TTS。这个结构很接近“文字留底、重要消息再升级”的调度层，而且 macOS、Linux、WSL2/Docker 都能自托管。

但它的默认“电话”是 Linphone SIP 账号 + Linphone 手机 App，不是直接拨蜂窝手机号/PSTN；语音链还是“录音→Whisper→LLM→Piper”，作者明确写了约 1–2 秒一轮，机器和 Agent 会话也必须在线。也就是说，架构值得借，但真正的普通电话兜底仍需再接 SIP trunk/PSTN，而且要另做“已读/已听/已确认”的统一状态机。代码

2. Speechmatics Agent STT：开始专门优化“电话 Agent 听错关键字段”这一层

Speechmatics 9 月 16 日正式推出 Agent STT。它不只是通用转写，而是针对电话号码、账号、地址、字母数字串等“听错一个字符就让工具调用全错”的场景，提供自定义词表、说话人归属和会话分段信号；官方称平均最终化约 350ms、覆盖 55+ 语言，并已接入 LiveKit 与 Pipecat。对耳机主入口和电话兜底都实用，因为能减少“用户明明说对了，但 Agent 传给工具的是错参数”这种高代价错误。

这里要把边界画清：这些延迟和准确率是厂商数据，我没有独立复测；它也不负责入耳检测、唤醒词、播放 ducking、通知未读状态或拨号。它更像一块可替换的“耳朵”，不是完整随身助手。官方发布

目前最值得试的组合思路是：手机端负责佩戴/播放/文字状态，后台 Agent 持续跑任务，独立升级器决定文字→语音→电话，通话层再接可靠的实时转写。 Ringback 已证明升级器可以单独做成工具层，但默认 SIP 还不能冒充真正的蜂窝电话。
